# 自動登出問題診斷指南

## 📋 問題描述

使用者在使用系統過程中，可能會遇到在沒有主動登出的情況下，突然被登出的情況。本指南將幫助您診斷和解決這個問題。

---

## 🔍 常見原因

### 1. Token Refresh 失敗
**發生情境**：Supabase 在背景自動刷新 access token 時失敗

**可能原因**：
- 網路連線不穩定
- Supabase API 暫時性延遲或錯誤
- 瀏覽器阻擋第三方 cookie
- Refresh token 已過期或無效

### 2. Session 驗證失敗
**發生情境**：定期驗證 session 有效性時失敗（每 15 分鐘）

**可能原因**：
- 暫時性網路問題
- Supabase 服務異常
- 瀏覽器 localStorage 被清除

### 3. JWT 過期時間過短
**發生情境**：JWT token 過期時間設定過短，導致頻繁刷新

**可能原因**：
- Supabase Dashboard 的 JWT expiry 設定過短
- 頻繁刷新增加失敗機率

### 4. 瀏覽器儲存被清除
**發生情境**：Session 資料從 localStorage 中消失

**可能原因**：
- 使用者手動清除瀏覽器資料
- 瀏覽器隱私模式
- 第三方擴充套件干擾

---

## 🛠️ 診斷步驟

### 步驟 1：檢查瀏覽器 Console 日誌

1. **開啟開發者工具**
   - Chrome/Edge：按 `F12` 或 `Ctrl+Shift+I`
   - Firefox：按 `F12`
   - Safari：`Cmd+Option+I`

2. **切換到 Console 標籤**

3. **搜尋關鍵字**，確認觸發登出的原因：

   **重要關鍵字**：
   ```
   force_logout
   token_refresh_failed
   session_validation_failed
   invalid_session
   ```

4. **解讀日誌訊息**：

   | 日誌訊息 | 原因 | 建議處理 |
   |---------|------|---------|
   | `token_refresh_empty_session` | Token refresh 返回空 session | 檢查網路連線 |
   | `token_refresh_failed_after_retry` | Token refresh 重試後仍失敗 | 檢查 Supabase 服務狀態 |
   | `session_validation_failed_will_retry` | Session 驗證失敗但會重試 | 觀察是否為暫時性問題 |
   | `invalid_initial_session_force_logout` | Refresh token 無效 | 需要重新登入 |
   | `signed_out_event` | 正常登出事件 | 正常行為 |

### 步驟 2：檢查 Network 請求

1. **開啟開發者工具的 Network 標籤**

2. **重現問題**（如果可以重現的話）

3. **檢查 Supabase Auth API 請求**：

   **關鍵 API 端點**：
   ```
   /auth/v1/token?grant_type=refresh_token
   /auth/v1/user
   ```

4. **檢查回應狀態碼**：

   | 狀態碼 | 意義 | 建議處理 |
   |-------|------|---------|
   | 200 | 成功 | 正常 |
   | 400 | 錯誤請求（可能是 refresh token 無效） | 需要重新登入 |
   | 401 | 未授權 | Token 過期，需要重新登入 |
   | 429 | 請求過多 | 降低請求頻率 |
   | 500/502/503 | 伺服器錯誤 | 檢查 Supabase 服務狀態 |

### 步驟 3：檢查 Supabase Dashboard 配置

1. **登入 Supabase Dashboard**：https://app.supabase.com

2. **選擇專案**

3. **導航至 Authentication > Settings**

4. **檢查 JWT 過期時間設定**：
   - 路徑：Authentication > Settings > **JWT Expiry**
   - **建議值**：3600 秒（1 小時）或更長
   - ⚠️ 如果設定過短（如 300 秒），會導致頻繁刷新和登出

5. **檢查 Refresh Token 設定**：
   - 路徑：Authentication > Settings > **Refresh Token Rotation**
   - **建議**：啟用（預設已啟用）

### 步驟 4：檢查 localStorage

1. **開啟開發者工具的 Application 標籤**（Chrome）或 Storage 標籤（Firefox）

2. **檢查 Local Storage**

3. **查找 Supabase 相關的 key**：
   ```
   sb-<project-ref>-auth-token
   ```

4. **確認是否存在**：
   - 如果不存在 → session 已被清除，需要重新登入
   - 如果存在 → 檢查其內容是否完整

## ✅ 解決方案

### 方案 1：已實施的改進（v1.0）

專案已經實施以下改進來減少自動登出的發生：

1. **Token Refresh 重試機制**
   - 當 token refresh 失敗時，會自動重試一次
   - 只有重試後仍失敗才會登出

2. **放寬 Session 驗證邏輯**
   - Session 驗證失敗時不會立即登出
   - 允許在下次驗證時重試
   - 避免因暫時性網路問題導致登出

3. **降低驗證頻率**
   - 從每 5 分鐘驗證一次改為每 15 分鐘
   - 減少驗證次數 = 降低失敗機率

4. **增強日誌追蹤**
   - 所有登出操作都會記錄詳細原因
   - 方便診斷實際問題

### 方案 2：使用者可以採取的措施

#### 如果是網路問題：
1. 檢查網路連線是否穩定
2. 嘗試切換網路環境（如從 WiFi 切換到行動網路）
3. 檢查防火牆或 VPN 是否阻擋 Supabase 請求

#### 如果是瀏覽器問題：
1. 關閉阻擋第三方 cookie 的設定
2. 停用可能干擾的瀏覽器擴充套件
3. 清除瀏覽器快取後重新登入
4. 嘗試使用無痕模式測試

#### 如果是 Supabase 配置問題：
1. 聯絡管理員檢查 Supabase Dashboard 的 JWT expiry 設定
2. 確認 Supabase 服務狀態：https://status.supabase.com

### 方案 3：管理員檢查項目

1. **檢查 Supabase JWT 配置**
   ```
   建議設定：
   - JWT Expiry: 3600 秒（1 小時）或更長
   - Refresh Token Rotation: 啟用
   ```

2. **監控 Supabase 日誌**
   - Dashboard > Logs > Auth Logs
   - 查看是否有異常的失敗率

3. **檢查 API 使用量**
   - Dashboard > Settings > API
   - 確認沒有超過配額限制

## 🚨 緊急情況處理

### 情況 1：所有使用者都無法保持登入狀態

**可能原因**：Supabase 配置問題或服務異常

**處理步驟**：
1. 檢查 Supabase 服務狀態：https://status.supabase.com
2. 檢查 Supabase Dashboard 的 JWT expiry 設定
3. 檢查專案的環境變數配置
4. 查看 Vercel 部署日誌

### 情況 2：特定使用者頻繁被登出

**可能原因**：使用者端的網路或瀏覽器問題

**處理步驟**：
1. 請使用者檢查 Console 日誌
2. 請使用者嘗試不同的瀏覽器
3. 請使用者檢查網路連線
4. 請使用者清除瀏覽器快取後重新登入

### 情況 3：登入後立即被登出

**可能原因**：初始 session 驗證失敗

**處理步驟**：
1. 檢查 Supabase service role key 是否正確
2. 檢查環境變數是否正確設定
3. 查看伺服器端日誌（Vercel Functions）

## 📊 監控和預防

### 定期檢查項目

**每週檢查**：
- [ ] Supabase 服務狀態
- [ ] 錯誤日誌中的 auth 相關錯誤
- [ ] 使用者回報的登出問題

**每月檢查**：
- [ ] Supabase Dashboard 的 JWT expiry 設定
- [ ] API 使用量和配額
- [ ] Supabase 套件版本更新

### 預防措施

1. **保持 Supabase 套件版本最新**
   ```bash
   npm update @supabase/supabase-js @supabase/ssr
   ```

2. **監控錯誤率**
   - 使用 Vercel Analytics 或 Sentry
   - 追蹤 `force_logout` 事件的頻率

3. **定期檢查 Supabase Dashboard**
   - Auth Logs
   - API 使用量
   - JWT 配置

4. **使用者教育**
   - 提醒使用者不要清除瀏覽器資料
   - 建議使用穩定的網路環境
   - 提供離線模式說明（如適用）
